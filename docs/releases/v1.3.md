# AegisVault Mobile 1.3

versionName **1.3**, versionCode **5**. Debug-signed test build / debug 签名测试版，沿用已有签名身份。

- Base64 decoding exposes strict mode and ASCII whitespace handling. Strict mode rejects whitespace even when ignore is selected; only non-strict + ignore accepts TAB/LF/CR/FF/VT/SPACE. Standard alphabet and padding remain validated.
- Empty and whitespace-only plaintext is valid. Passwords reject only the empty string; whitespace and Unicode remain exact, without trimming or normalization.
- Malformed input Unicode, invalid Base64 and decoded invalid UTF-8 produce distinct Android errors. Existing 1 MiB plaintext, 2 MiB encoded-input and 64 MiB KDF limits remain in place.
- Minimal bilingual switches, reachable scrolling, whitespace-preserving paste/copy/use-result and cancellation when options change.
- Offline migration accepts nonempty whitespace passwords. Production still accepts formal AGV1 only; historical readers remain isolated in the migration tool.

Validation: 47 Android JVM test methods, 6 offline migration tests, lint and APK build; 783 cases compared against the actual frozen desktop CryptoService, including all four Base64 mode combinations and bidirectional AGV1 text exchange. Physical-device acceptance is **NOT RUN** when no device is connected; local JVM/build evidence does not replace it. Settings recovery (#10), file features and device acceptance remain outside this version's implementation scope.

中文：本次统一 Base64 四种模式组合、空字符串及空白口令语义，保留实际桌面 decoder 的填充规则和非零丢弃位行为。仅“关闭严格模式 + 忽略 ASCII 空白”允许六种 ASCII 空白；不会忽略其他 Unicode 空白。非法输入 Unicode、Base64 语法及解码后 UTF-8 错误分别报告。
